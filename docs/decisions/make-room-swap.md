Decision: Swapping a title for a smaller release queues its movie file, or each of its episode
files (specials and unnumbered files aside), and searches them one at a time at least 15 seconds
apart, leaving out for an hour an indexer that says it's at its limit, while downloads are on. A
release is judged by the title's profile without comparing it with the file on disk, and turned
down above 1080p, above three quarters of the copy or 4.5 GB an hour, or when its name or size
doesn't say. The best is grabbed and replaces the copy through the usual upgrade check (the same
length, the old file to the trash). The title stops being monitored when the swap starts. Only
titles on the wanted list can be swapped, as the search needs their profile. Searches that
already compared releases with the file on disk keep doing so; only swaps skip it.

Why: A release encoded from the source is better for its size than shrinking the copy, and
costs no GPU time; going through the normal grab and replace keeps every safety check of an
upgrade. Series replace only through single-episode releases, so they're swapped episode by
episode, slowly, so indexers' limits hold. Without unmonitoring, the next upgrade search would
fetch the large copy back.
