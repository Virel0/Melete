Decision: Every playlist import looks for each track in the library before asking for it, whether or not it makes a playlist, matched as POST /aoide/match matches (its ISRC, else its title, artist and length); a track found isn't asked for and counts as in the library already. Only the libraries the importer may see are looked in, so a track only in a library hidden from them is asked for as any other. A request MusicBrainz turns down as asked (a 4xx other than 404) isn't retried: the track is listed as not matched with why, and a refused ISRC lookup leaves the track to its title search. Artists in a playlist file are split at semicolons as well as commas.

Why: An import without a playlist asked for every track, and a song request isn't checked against what's on disk, so a song the library had was searched for and downloaded again once approved. Retrying a refusal only cost two minutes a track for the same answer, which is how an include the ISRC lookup doesn't take made every track with an ISRC slow and unmatched; Exportify now joins artists with semicolons. Looking in what the importer may see, rather than every library, keeps an import's counts from telling a limited user what a hidden library holds.
