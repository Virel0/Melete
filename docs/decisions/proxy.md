Decision: Melete can send chosen services through one proxy (`MELETE_PROXY_TYPE` socks5, http or https; `_HOST`, `_PORT`, and an optional `_USERNAME` and `_PASSWORD`, the password sealed and never shown), each service switched on by its own setting (`MELETE_PROXY_TMDB` and the rest) and direct by default, local ones (Sonarr, Radarr, Lidarr, Prowlarr, slskd, FlareSolverr) included, with a warning that a proxy outside can't reach the local network and would carry their keys. Every HTTP client starts in one module (`proxy::builder`), which a test checks by reading the sources; SOCKS5 is always socks5h, so the proxy looks names up. A service switched on only ever goes through the proxy: a switch with no proxy is refused when saved, a client with no proxy to use refuses every connection, and a connection the proxy doesn't make fails with words naming the proxy's address, never its login or the failure's own text. Admin health's System shows `proxy_down` while the proxy doesn't answer, and a service's Test that failed there says so. The proxy's Test asks api.ipify.org through it which address the outside world sees, only when an admin presses Test. Saving applies at once: clients made per request take the new setup, and the lasting ones are built afresh. The seedbox's SFTP stays direct, and indexers get a choice of their own.

Why: The household's address is what outside services see of it; a proxy hides it from those an admin picks. A kill switch that never goes direct is the only kind worth having for privacy, and one place building every client is what keeps a new service from skipping the choice. Local services can be chosen because some sit elsewhere, but stay direct unless asked.
