Decision: Melete can send chosen services through one proxy (`MELETE_PROXY_TYPE` socks5, http or https; `_HOST`, `_PORT`, and an optional `_USERNAME` and `_PASSWORD`, the password sealed and never shown), each service switched on by its own setting (`MELETE_PROXY_TMDB` and the rest) and direct by default, local ones (Sonarr, Radarr, Lidarr, Prowlarr, slskd, FlareSolverr) included, with a warning that a proxy outside can't reach the local network and would carry their keys. Every HTTP client starts in one module (`proxy::Http`), which clippy and a test reading the sources hold every other module to; SOCKS5 is always socks5h, so the proxy looks names up. A service switched on only ever goes through the proxy: a switch with no proxy is refused when saved, a client with no proxy to use refuses every connection, and a connection the proxy doesn't make fails with words naming the proxy's address, never its login or the failure's own text. Admin health's System shows `proxy_down` while the proxy doesn't answer, and a service's Test that failed there says so. The proxy's Test asks api.ipify.org through it which address the outside world sees, only when an admin presses Test. A Test with values that move any service to another address (URL, host, port, proxy type, issuer) leaves out its stored secrets and usernames the body doesn't give, and says so. Saving applies at once to every client from its next request, those kept for long jobs (imports, searches for everything missing) included, as each is made again from the setup in use whenever that changes; clippy's disallowed methods and types keep any other module from making a reqwest client. Each indexer has its own switch (`indexers.proxy`, off by default, kept across Prowlarr imports), followed by its searches, its tests and the fetching of the torrents its results link to; a result whose indexer was removed is fetched through the proxy whenever one is set, as its way is no longer known. Uindex and feeds that turn Melete away are fetched by FlareSolverr, which is handed the proxy's address in its `proxy` field (HTTP or SOCKS5) only when it answers as FlareSolverr 3.2.0 or later, the first since its 3.0 rewrite to read that field; a proxy with a login (its password never goes to FlareSolverr, whose requests may be logged and may cross the network in the clear), an HTTPS proxy, or a solver that may not read the field stops the request instead. The seedbox's SFTP has its switch too (`MELETE_PROXY_SEEDBOX`): SSH goes over a plain connection from the same module (`proxy::stream`, with hyper-util's SOCKS5 and CONNECT handshakes, which reqwest already builds in), under the same kill switch, and clippy holds every other module off russh's own connect; `melete seedbox host-key` reads the proxy's settings from the environment and the database (read-only) before it connects. A copy from the seedbox keeps the connection it started on, so one running when the switch changes finishes that way; the next follows the switch.

Why: The household's address is what outside services see of it; a proxy hides it from those an admin picks. A kill switch that never goes direct is the only kind worth having for privacy, and one place building every client is what keeps a new service from skipping the choice. Local services can be chosen because some sit elsewhere, but stay direct unless asked.
