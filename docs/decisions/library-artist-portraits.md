Decision: Artists in the library get a portrait: `portrait` and `portrait_credit` on every music artist item (`GET /music/artists`, `/music/artists/{id}`, and pins and Replay, which share that shape), served at `GET /music/artists/{id}/portrait` to those who may see the artist (404 otherwise, as their page). A picture of their own comes first, whatever the settings: when the present albums of theirs a user may see all sit in one folder, not the library's root, holding artist.jpg, artist.png, folder.jpg or folder.png (case aside), as scans note beside each album (`music_albums.artist_file`); it has no credit, is served only from inside the library, and Commons isn't asked about them. Else, with `MELETE_ARTIST_PORTRAITS` on, decision 303's lookup runs in the background (the `artist-portraits` task) for artists in the library with a MusicBrainz id and no picture of their own: at most 20 a run, once an hour, those never looked up first, then those looked up longest ago, with the same rules for keeping what was found (30 days), a none (a week), a failed lookup (kept nowhere) and a picture Commons failed to give (a day). A lookup for the library isn't a search listing the artist, so the MusicBrainz id route still serves only what a search listed. Housekeeping never forgets an artist in the library while the setting is on, and they don't count towards the 2000; an artist gone from the library is forgotten 30 days after a search last listed them, and every one when the setting is off. What leaves the server is what decision 303 says: the artist's MusicBrainz id (to MusicBrainz), its Wikidata item's id (to www.wikidata.org) and the image's file name (to Commons).

Why: Artist pages and lists had no picture. Looking up in the background keeps a page from waiting on MusicBrainz's one request a second; 20 a run holds matching, which shares that pace, up by about 20 seconds an hour, covers a library of 2,000 artists in about four days, and then keeps up with looking them up again (about 180 a day for 2,000 artists if half have none). A picture the household put beside the music is what they chose, and sends nothing out; asking that all of an artist's albums share its folder keeps an artist with albums in several places from taking one of them for theirs. Working it out from the albums a user may see means a picture never hints at albums in libraries hidden from them, and not counting a library lookup as a listing keeps the MusicBrainz id route from answering differently for an artist only in a hidden library.
