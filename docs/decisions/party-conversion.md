Decision: A conversion asked for through a link of a household device or guest in a watch party that plays the file runs under a key made of the party, the file's version and the whole conversion plan, so the party's viewers whose plans are the same share one ffmpeg run; anyone else, and any viewer whose plan differs (another audio track or sound, another height or bitrate, subtitles drawn in), has their own. Each viewer keeps their own link, checked as before (a guest's against the party's cap at every request). The run counts its viewers, pauses and deletes segments by where the slowest one is, and stops once none has asked for a minute. A viewer asking for a segment before where the shared run starts moves it there, as a party jumping back does, unless that viewer hasn't yet caught up with the run while others are watching it (a player still loading what came before everyone jumped ahead): then that viewer gets a run of their own, stopped as soon as they catch up.

Why: A party's members play the same file at the same moment, so separate conversions encode the same picture twice. Keying on the whole plan rather than on what was asked means a guest's cap can never be got round by sharing: a guest held lower is planned lower and runs apart.
