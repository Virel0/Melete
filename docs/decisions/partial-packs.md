Decision: Amends decisions 35 and 37 for season packs. When some of a season is on disk or on its way, an accepted pack for it (from a season search, RSS sync, Search all missing or a request) is grabbed when it holds at least one missing episode: one TMDB lists as aired, not left out on its own, with no file on disk in any folder known by the title's ids and no download on its way or unsettled. It's taken for those episodes and for each one whose only file, in the title's own folder and holding that episode alone, the pack's copy is an upgrade of, judged as an upgrade search would judge it against that file (the pack's quality rank, revision and custom format score); that file goes to the trash once the upgrade is confirmed (decision 37). Every other episode is left out, so better files on disk stay where they are. The download records the episodes it's for (`downloads.episodes`), and only the pack's files whose own names give that season and episodes, all of them taken, are brought home and checked for running time; extras, anything in an extras folder and anything else stay on the seedbox. The pack is downloaded whole: the Deluge client doesn't set file priorities. A season whose aired episodes TMDB doesn't list isn't taken in part, and a pack for a season with nothing missing that isn't on its way is passed over. Search all missing notes what was taken ("Title, season 2: took episodes 6, 7 from a pack; kept 1–5 on disk"). A season pack with nothing of its season on disk or on its way is grabbed whole, as before. What's on its way counts by each download's own name too, every episode of a multi-episode release, but only downloads recorded for the season: one recorded for another is brought home as that season's. Amends decision 306: a switch of order (or TMDB changing the group followed) waits while a pack taken in part is unsettled, or a download's replaced files haven't been dealt with, in a season it renumbers at all, since both are kept by episode number; for a series with files numbered from the first episode, every season from the first one renumbered counts, since those files count through the seasons before theirs. And a replaced file whose season and episode aren't what they were when the upgrade was grabbed is kept, whatever renumbered it. The running-time check reads a file named with numbers from the first episode as the episode the order followed makes it, and holds the download back when that can't be told.

Why: A pack holding the missing episodes was passed over whenever any file of its season was on disk, as an upgrade of every file there it couldn't be, so a partly missing season never got its missing episodes. Taking only what the pack adds fills the gaps without replacing a better copy. Placing files only by their own names fails closed: a file that can't be told to be a chosen episode never reaches the library.
