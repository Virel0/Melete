Decision: Admins are told when a library stops responding and when it answers again, by a webhook, by email, or both, each an outside service of its own under Outside services and off until set. The webhook is POSTed the alert as plain text with a `Title` header (as ntfy takes it) or as JSON (`title`, `message`, and `content` for Discord); its address is kept as a secret, since it's often the only key, is never shown in an error, redirects aren't followed, and it goes direct, not through the proxy. Email goes through the mail server set up, with STARTTLS required or TLS from the start, the login sealed like other secrets, and a greeting that names no machine (`localhost`). What leaves the server is the alert alone: the library's name, what happened and why. Settings are read when an alert is sent, so a change in the web UI applies at once; each alert is sent on its own, given 20 seconds, and a failure is logged without holding up the library check. A Test sends a test alert that way.

Why: A library that stopped responding was noticed only by someone looking. A webhook reaches a phone through ntfy or a home automation without a new account, and email reaches anyone; neither sends anything until an admin sets it up.
