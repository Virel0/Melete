Decision: Melete reads each library's folder every minute, on a thread of its own and with a 15-second limit, and never starts a second read of a folder while one is still out. A folder that doesn't answer in time, can't be read or is empty marks its library as not responding (`libraries.unreachable_since`, `unreachable_why`, written only after the read has come back or given up) until a read finds something in it. While a library isn't responding, nothing new reads it: scans are refused and a walk in progress is given up, stream links and streams for its files are refused with 503 and "the <name> library isn't responding", and its disk space isn't measured. Other reads of library folders on request (streams, artwork, disk space) run off the async threads within the same limit, and one that times out marks the library at once.

Why: A library share that freezes makes every read of it wait with no end: requests, scans and copies into it could hang for hours while nothing said anything was wrong. Reading the top folder costs one directory read a minute, which a share serves from its cache; an empty folder counts because an unmounted share looks empty, and writing into it would fill the host's disk.
