# Melete design

One Rust service, run as one Docker container, that replaces Jellyfin, Sonarr, Radarr,
Lidarr and Prowlarr on a home media server. It serves the library to native client apps
(Mneme for video, Aoide for music) and automates finding, downloading and importing media.

**What must never go wrong:** the existing library is never renamed, moved or deleted
by the app; a download is never imported to the wrong title; seedbox and indexer
credentials never leave the server.

## Why one app

A typical stack of separate apps fails because four apps guess about each other:

- Sonarr and Radarr see a torrent finish on a seedbox, but the file reaches the media
  server later through a separate sync script and is then moved again, so imports work
  only some of the time.
- Jellyfin rescans to find out what the arrs did, and its matching disagrees with theirs.
- The same settings (paths, quality, indexers) are configured in several UIs.

One app with one database removes the guessing: a file is in the library because the app
put it there, and every download is a tracked job from search to import.

| 22 | Every file is probed with ffprobe in the background (4 at a time, alongside TMDB matching) and the result stored against its size and date; failures are stored too, timeouts are retried. `GET /api/v1/files/{id}` returns codecs, resolution, HDR type, tracks and duration, probing on the spot if needed. jellyfin-ffmpeg 8 is installed from Jellyfin's repository, pinned, with the signing key's fingerprint checked. *Amended 2026-10-25:* Dolby Vision streams also carry their profile and fallback picture; files probed before that was recorded are probed once more | Apps need codec facts to choose direct play or transcoding; a missing ffprobe must not be recorded as thousands of broken files | 2026-10-24 |
| 23 | Transcoding is HLS: the playlist lists the whole file in fixed 6-second segments up front (keyframes forced on boundaries), so players know the length and can seek; ffmpeg encodes ahead and restarts at a far seek, pauses 3 minutes ahead, deletes passed segments and stops after a minute idle; at most 4 run. Output is H.264 (NVENC, or libx264 on the CPU) with AAC in MPEG-TS; HDR is tone-mapped to SDR on the GPU. On request (`video_codec`) it is HEVC (hevc_nvenc or libx265, tagged hvc1) in fragmented MP4, keeping HDR10 and HLG in 10 bits, Dolby Vision's included where its base layer is one (profiles 7, 8.1 and 8.4; the output is plain HDR10 or HLG, without Dolby Vision metadata); profile 5, which has no other picture, and burned-in subtitles are tone-mapped, and an SDR base layer (8.2) never is. A copied profile 5 file is tagged dvh1, so players without Dolby Vision refuse it rather than show wrong colours, and the file info says what players without Dolby Vision see (`dolby_vision.fallback`), or `copy`: the file's own H.264 or HEVC video unchanged and only the audio converted, from MKV and MP4 only. Copied video can only be cut at its keyframes, so its playlist lists keyframes about 6 s apart, found by seeking through the file's index (one seek per 6 s, kept per file version; refused past 30 s between keyframes); ffmpeg writes a chunk per keyframe and a segment is put together from its chunks when asked for. Every run of a session lines up exactly with the others: copies keep the file's timestamps, no muxer shifts a run's start, and fMP4 fragments carry their real times with no edit list, so every run writes the same init section. The playlist URL carries a stream token, like direct play | Works with AVPlayer, VLC and browsers; bounded GPU, CPU and disk use. Copying saves the GPU and keeps the picture when only the container or the audio is the problem. Two ffmpeg behaviours are relied on and pinned by tests: `-ss` seeks 3/23 s early when a stream has B-frames, and the MP4 muxer rewrites the first frame of each fragment unless told to skip the sidx (wrong for open-GOP HEVC). Copied H.264 repeats its parameter sets at every keyframe, since MPEG-TS needs them in the stream and open-GOP keyframes aren't IDR frames. After a seek into open-GOP video, the few frames shown just before the keyframe need the segment before it and are skipped or concealed by the decoder. On the CPU (no NVENC), profile 5 is tone-mapped with jellyfin-ffmpeg's `tonemapx`, which applies its Dolby Vision metadata as `tonemap_cuda` does on the GPU; an ffmpeg without `tonemapx` (checked at startup) falls back to zscale, whose profile 5 colours are wrong | 2026-10-24 |
| 24 | Subtitles: `GET /files/{id}/subtitles` lists embedded tracks and files beside the video; text tracks are served as WebVTT behind the stream token (converted once, cached in `/config/subtitles`); any track can be burned into a transcode (`burn_subtitle`), picture tracks overlaid from the file and text tracks rendered from a cached ASS copy, keeping styling and positions, with the fonts attached to the video (pulled out once per file version into `/config/subtitles/fonts-…`, each under a name Melete picks, never the name the file gives; a video without fonts is remembered as such; if fonts can't be pulled out, the burn goes ahead with system fonts). *Amended 2026-10-25:* after each scan the cache drops entries for files no longer in the library or that changed (pulled-out fonts included), failure markers after a day, and abandoned temporary files External tracks are identified by a hash of their file name; conversions of one track are shared and failures remembered for 10 minutes. Tone mapping and scaling stay on the GPU; frames come back to the CPU only for the overlay | Players handle text tracks themselves; AVPlayer can't show PGS. Known limit: after a seek restart, a picture subtitle already on screen at the seek point waits for the next event | 2026-10-25 |
| 25 | Radarr and Sonarr lists are imported into a wanted list (movies; series with season monitoring and per-episode overrides) by `POST /api/v1/import/{radarr,sonarr}` with the URL and API key, which is used once and never stored. Entries link to adopted folders by folder name; the *arrs' TMDB/TVDB ids go into `arr_*` columns the scanner doesn't rewrite, and matching prefers them, redoing non-manual matches that disagree. Root folders map to libraries by name, path ending or an explicit mapping; folders link only within the mapped library or by a unique name. A re-import removes entries the *arr no longer lists (never all at once, never ones added by hand). Redirects aren't followed, so the key only goes to the given URL | Nothing has to be re-added, and the *arrs' curated ids settle ambiguous folders. Re-running is safe | 2026-10-25 |
| 26 | Release names are parsed by one pure function (`src/release.rs`) into title, year, episodes (standard, packs, anime absolute and batches, daily), resolution, source, remux, HDR/DV, codecs, audio and channels, audio and subtitle languages, proper/repack, version and group; quality names follow Radarr/Sonarr (a resolution without a source counts as HDTV, as in Sonarr). `GET /api/v1/releases/parse` shows the result | Every release decision (searches, grabs, RSS sync, upgrades) rests on these facts; matching Radarr/Sonarr's quality names lets their profiles be imported | 2026-10-25 |
| 27 | Custom formats and quality profiles are imported from Radarr and Sonarr (`POST /api/v1/import/{radarr,sonarr}/profiles`) and kept per app, since the apps number sources and languages differently. Decisions follow Radarr's rules and list every format, score and reason; `POST /api/v1/profiles/{id}/evaluate` shows one. *Amended 2026-10-25:* formats and profiles can also be made and changed in Melete (`POST`/`PUT`/`DELETE` on `/api/v1/custom-formats` and `/api/v1/profiles`), checked as an import checks them; those are Melete's own (`origin`), and re-imports never overwrite or remove them. `source` then says which kind of titles they're for. Formats gain a `subtitles` condition, which Radarr and Sonarr lack. *Amended 2026-10-25:* a wanted title can be given a profile chosen in Melete (`PUT /api/v1/wanted/{movies,series}/{id}/profile`), which searches and RSS use over the *arr's and re-imports keep; `POST /api/v1/profiles/presets/anime` makes an anime profile (1080p, 2160p when available; dual Japanese and English audio over English over Japanese with English subtitles; raws refused; releases not naming subtitles still qualify) | Imported profiles carry years of existing tuning; reproducing the apps exactly makes the switch safe. A format silently dropped (say a -10000 one) would let in what it was built to keep out | 2026-10-25 |
| 28 | Indexers are imported from Prowlarr (`POST /api/v1/import/prowlarr`): each torrent indexer becomes a Torznab feed at Prowlarr's `/{id}/api`, used with Prowlarr's API key, which Melete stores (in the database, never in responses, errors or logs). Usenet indexers are skipped. The Torznab client (`src/torznab.rs`) is the only code that talks to indexers: 30-second timeout, no redirects (the key is in the query string), replies capped at 16 MiB, errors stripped of URLs, download links never returned. Checked end to end against Prowlarr 2.6 with a generic Torznab indexer pointed at a local fake tracker | Prowlarr already keeps the tracker definitions and sessions; its per-indexer feeds give Melete each indexer on its own (for per-indexer results and errors) without re-implementing scraping. Prowlarr's key is the only credential its feeds take | 2026-10-25 |
| 29 | Searches (`POST /api/v1/wanted/{movies,series}/{id}/search`) ask every turned-on indexer at once, by IMDb/TMDB/TVDB id where it takes one, else by title. A result counts as the wanted title only if its parsed title equals the title or TMDB's original title (case, accents, punctuation, apostrophes, a leading article and Sonarr's "(2005)" aside), its year is exactly the title's (movies must give one, and a wanted movie without a year matches nothing: remakes come a year apart), and it's the kind searched for: a movie, the episode, or a pack holding the season. Anime absolute numbering and dated episodes are refused until they can be mapped. Every result is decided on with the title's profile, against the best file on disk where it would go (every episode a multi-episode release covers; a file whose quality can't be told from its name blocks upgrades), and stored with its decision for 30 days; download links and guids are stored for grabbing and never shown. Titles carry their original language from Radarr/Sonarr, which untagged releases are assumed to be in. *Amended 2026-10-25:* a movie's year may be one off (a festival year) when TMDB lists no other film of that title from that year; in a season search an episode range holding every episode TMDB lists counts as the season; a bare `E05` is an episode, never a movie; a file whose name gives no quality is judged from ffprobe as the best quality at its resolution (so only a higher resolution replaces it), and a show's files that look numbered but couldn't be stop episode upgrades | A download must never be imported to the wrong title, so matching fails closed: an unclear result is rejected with a reason rather than guessed at. | 30 | Downloading is off unless `MELETE_DOWNLOADS=on`, which then needs Deluge's web UI address and password or Melete won't start. Grabbing (`POST /api/v1/releases/{id}/grab`) takes an accepted search result only: Melete fetches the torrent from the indexer itself (the seedbox can't reach Prowlarr) and adds it to Deluge through the web UI's JSON API, or follows it if Deluge already has it. Downloads are keyed by the info hash Deluge gives them (for hybrid and v2 torrents, libtorrent 2's name isn't the SHA-1 of the info dictionary), checked first against the hash computed from the torrent or magnet, so none is grabbed twice. Every minute Deluge is asked about downloads in progress; finished ones (not in Deluge's Error state, which a failed move also sets) become completed with their save path and files; one Deluge hasn't listed for 30 minutes becomes failed. The client reconnects the web UI to its daemon when it loses it. A remote Deluge must be https. Checked against Deluge 2.2 on an isolated network | The web UI's JSON API is what seedboxes commonly expose; the daemon's own protocol would need another port opened. Hashes in the database, not folder contents, say what was fetched, which ends the re-download-forever flaw of a script that mirrors a folder | 2026-10-25 |
| 31 | The seedbox is reached over SFTP (`russh`, pure Rust) with its host key pinned in `MELETE_SEEDBOX_HOST_KEY` as OpenSSH writes it (SHA256:...). SFTP is the only way files come from the seedbox; rsync isn't used. Any other key ends the connection during the handshake, before the password is sent; nothing is trusted on first use. `melete seedbox host-key <host> [port]` shows the key a server presents without sending anything, so an admin can check it with the provider and pin it. The host key has to be Ed25519 or ECDSA: RSA host keys aren't supported, so the RSA library, with a timing weakness that has no fix yet (RUSTSEC-2023-0071), stays out of the build; Melete only checks the server's signature and signs in with a password, so it never holds an RSA private key, and nearly every SSH server offers an Ed25519 key too. The seedbox settings are optional but all-or-nothing: without them, downloads are followed but stay on the seedbox. `MELETE_SEEDBOX_PATHS` maps Deluge's folder for finished torrents to the same folder over SFTP, and nothing outside it is reachable. `POST /api/v1/seedbox/test` signs in and checks the folders. Checked against OpenSSH 10.3: the fingerprint matches `ssh-keygen`'s, and after the server's keys changed Melete refused it and no password reached it | lftp's `sftp:auto-confirm yes` would hand the password to any impostor (decision 13). A pure-Rust client avoids building libssh2 and OpenSSL into the image; its crypto (aws-lc-rs) is already used by rustls | 2026-10-25 |
| 32 | Finished downloads are copied home one at a time over SFTP, straight into the folder they belong in: a movie's adopted folder, or a new "Title (Year)" folder in its library; an episode into the folder that season's files are already in (or loose, if the show keeps them loose), else "Season NN". Only videos and subtitles come, not samples, Screens folders or info files, and only regular files: links on the seedbox are refused (checked by file type exactly; russh-sftp's `is_regular` says yes to links). Each file is written under a hidden `.name.<download>.melete-part` (scans skip it; one per download, so releases never mix), opened without following links, resumed after an interruption, flushed, synced and its length checked, made u=rw,g=rw,o=r, and put in place with a hard link or, where links don't work, a rename with RENAME_NOREPLACE; both fail rather than replace a file, and where neither is available nothing is imported. New folders are u=rwx,g=rwx,o=rx. Anything already at a name (a file, a folder, a dangling link) stops the import unless this download recorded placing it; nothing in the library is overwritten, moved or deleted, so an upgrade leaves the old file beside the new one. An empty or missing library folder counts as an unmounted share and is never written to. Network and read-only-library problems retry with a growing wait (up to 6 hours, 12 tries); problems that can't fix themselves fail with the reason. A restart resumes interrupted copies. Checked against OpenSSH 10.3: a 4 GB copy killed partway resumed and came out identical | Decision 8's design, with decision 3's promise kept at the file-system level rather than by care: the link call itself can't replace a file. Group-writable modes match what the arrs' imports gave files | 2026-10-25 |
